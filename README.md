# Offline SLH-DSA Signing Device

An Arduino Nano ESP32 that reads `message.txt` from a microSD card, signs it with a post-quantum SLH-DSA key held on the device, and writes `message.txt.sig` back to the card.

---

## Desktop CLI (`cli/`)

A desktop prototype of the signing logic, using the `SLH-DSA-SHA2-128f` parameter set. Run all commands from the `cli/` directory.

### Generate a keypair

```bash
cargo run -- keygen <secret-key-path>
```

Writes the raw secret key to `<secret-key-path>` and prints the public (verifying) key as hex to stdout.

### Sign a message

```bash
cargo run -- sign <secret-key-path> <message> <signature-path>
```

Reads the secret key from `<secret-key-path>`, writes the raw signature over `<message>` to `<signature-path>`, and prints the hex-encoded signature to stdout.

### Verify a signature

```bash
cargo run -- verify <public-key-hex> <message> <signature-path>
```

Reads the raw signature from `<signature-path>` and verifies it over `<message>` against the hex-encoded public key.

### Run tests

```bash
cargo test
```

## Nano firmware (`nano-signer/`)

Sign a hardcoded message on the ESP32-S3 itself, using `SLH-DSA-SHA2-128f` and the same dev keypair generated by the desktop CLI above (embedded at build time from `nano-signer/keys/`; see that phase's notes on why this is a throwaway bring-up key, not a real identity).

Build, flash, and open the serial monitor from `nano-signer/`:

```bash
espflash flash --monitor target/xtensa-esp32s3-none-elf/debug/nano-signer
```

With the monitor attached, press **`s`** to sign. Expected sequence:

- Blue LED on while signing.
- On success: blue off, a signature summary printed to the serial log, then solid green for about half a second before turning off.
- On failure: blue off, `signing failed` printed, then solid red for about half a second before turning off.

Sample log output (the signature is truncated to its first 8 bytes, since the full `SLH-DSA-SHA2-128f` signature is ~17 KB, more than enough to prove signing works without flooding the serial monitor):

```
signed 40 bytes with public key a6ebfddc6e1db3639692c755ea0bd0be57876503d3cca16e6522b0a41c626446
signature (17088 bytes): 5879598e1307d8a7...
```
